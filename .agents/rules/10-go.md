# Go Development Rules

Go 実装時の主要ルール。詳細は [`CLAUDE.md`](../../CLAUDE.md) および [`internal/CLAUDE.md`](../../internal/CLAUDE.md) を参照。

- **フォーマット**: `goimports -w <file>` を使用する（`gofmt` は不可。`goimports ./...` は通らない）。
- **Lint**: `golangci-lint run ./...` で警告 0 にする。並列実行不可のため他で実行中の場合は待つ。
- **テスト実行**: `go test -tags test ./...` を使用する（`-tags test` が無いと対象が変わる）。
- **TDD & カバレッジ**: Red -> Green -> Refactor を遵守。`cmd/` と `internal/infrastructure/` を除く全パッケージで分岐カバレッジ (C1) 80% 以上。
- **テスト配置**:
  - Domain: `internal/domain/*_test.go`
  - Use cases: `internal/usecase/*Interactor_test.go`
  - Presenter / Controller: `internal/adapter/*/`
- **アーキテクチャ依存方向**: infrastructure -> adapter -> usecase -> domain。逆流させない。
- **非決定的なテストの禁止**:
  - シャッフル順序（`Reset()` / `Shuffle()` 後）を前提にしない。手札は `AddCard` で直接構築する。
  - 乱数分岐は最大 1000 回のリトライループで両方の分岐を通す。
