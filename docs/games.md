- **Omaha Hi-Lo / 8 or Better**: Same domain (`internal/domain/Omaha.go`) as Omaha Hold'em with the `hiLo` flag enabled via `domain.NewDefaultOmahaHiLo()` (constructor pattern mirrors Razz / SevenCardStud). Identical progression and 2-hole + 3-community combination rule for both the high hand and the low hand. At showdown, in addition to the standard high evaluator (`EvalBestHand`) the engine evaluates the best 8-or-better A-5 lowball hand (`OmahaPlayer.EvalBestLowHand`) — five distinct ranks all ≤ 8 (Ace = 1), no pairs allowed; straights and flushes are ignored on the low side. Each side pot is split 50:50 between the high winner and the qualifying low winner (`Omaha.distributeHiLoPots`); odd chips go to the high side. If no player qualifies for a low, the high winner takes the full pot. A "scoop" (same player wins both halves) collects the entire pot. Reuses the Omaha CUI/Web controllers and presenters; lo-hand cards and Hi/Lo won-amount split surface in the existing `HoldemResult` via optional `LowQualifies`, `LowBestHand`, `HiWonAmount`, and `LowWonAmount` fields.
- **5 Card Omaha (Big O)**: Same domain (`internal/domain/Omaha.go`) as Omaha Hold'em, parameterised to deal **5** hole cards instead of 4 via `domain.NewDefaultBigO()` (sets the `holeCards` field; thin constructors live in `internal/domain/BigO.go`). All other rules match Omaha: must use exactly 2 hole cards + 3 community cards (now C(5,2)×C(5,3) = 100 combinations evaluated, up from 60). Hand evaluation (`OmahaPlayer.EvalBestHand`) is hole-card-count agnostic (`combinations()`), so no new evaluator is needed; pre-flop strength scoring and Monte Carlo equity (`calcOmahaEquityWithHoleCount`) generalise to 5 cards. Reuses the entire Omaha use-case/adapter stack (interactor, web/CUI controllers and presenters); the CUI title switches to the Big O variant based on `GetHoleCardCount()`. The `holeCards` field is persisted in the JSON wire format so KV-restored sessions keep dealing 5.
- **5 Card Omaha Hi-Lo (Big O)**: Big O with the `hiLo` flag enabled via `domain.NewDefaultBigOHiLo()`. Combines the 5-hole-card deal with the Omaha 8-or-Better split-pot logic (`EvalBestLowHand`, `distributeHiLoPots`) — identical high/low evaluation and 50:50 split rules to Omaha Hi-Lo, but over 5 hole cards.

- **Crazy Pineapple Poker (クレイジーパイナップル)**: Pineapple Poker のバリアント。ディスカードのタイミングが「フロップベッティング終了後」（ターン配布前）に変わる点だけが異なる。Backed by the same `internal/domain/Pineapple.go` struct with the `discardAfterFlopBetting` flag set (constructors: `NewCrazyPineapple` / `NewDefaultCrazyPineapple`). ## Action Log (棋譜)

All games support a `log` command that returns a cumulative action log of every action taken during the current game session. The log reveals all hidden cards (e.g., face-down cards, opponent hands) so players can review the full history of the game after the fact. Each log entry contains the turn number, player index, action type, a human-readable detail string, and optionally the cards involved in the action.
